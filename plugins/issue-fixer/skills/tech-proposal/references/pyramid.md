# 金字塔原理 + 突出重点 · 结构化表达门禁

> 来源：《金字塔原理》（Barbara Minto）。本文把它落成技术方案的**可执行门禁**。
> 一句话目标：**让评委 30 秒抓住结论、5 分钟看懂全局、任何一节单独拎出来都能读懂**。做不到就是没写完。
> 配套：图的部分见 `diagram-cookbook.md`（《用图表说话》）；本文管「文字怎么组织、重点怎么突出」。

## 一、金字塔四原则（先搭骨架，再填内容）

金字塔＝一个塔尖（中心结论）统领几组塔身（分论点），每组再由塔基（论据/数据/图）支撑。四条原则决定这座塔立不立得住：

| 原则 | 含义 | 在方案里长什么样 | 违反的样子（评审会打回） |
|---|---|---|---|
| **① 结论先行** | 每篇 / 每节只有一个中心思想，放最前面 | 文档开头一段执行摘要；每节第一句给判断 | 背景铺三屏才说要干什么；选型列一堆不给结论 |
| **② 以上统下** | 上层论点是下层的概括，下层为上层提供支撑 | 章节标题 = 该节结论；节内每个子点都在支撑标题 | 标题写「方案设计」，正文却在讲无关的历史包袱 |
| **③ 归类分组（MECE）** | 同层各组**相互独立、完全穷尽**，不重叠不遗漏 | 非目标分 ✅/⏭️/❌ 三档；风险按 工程/安全/稳定性 三维 | 三条风险其实是一条的三种说法；漏了异常链路 |
| **④ 逻辑递进** | 同组内按一种明确顺序排列 | 上线顺序按**时间**、模块按**结构**、风险按**程度** | 同一组里一会儿按时间一会儿按重要性，读者跟不上 |

**逻辑递进的四种合法顺序**（组内只能选一种，别混）：

- **演绎顺序**：大前提 → 小前提 → 结论（讲「为什么必须这么做」时用）。
- **时间顺序**：第一步 → 第二步 → …（上线步骤、数据流、Phase 1..N）。
- **结构顺序**：按空间/模块拆（前端 / server / worker，或按页面模块）。
- **程度顺序**：最重要 → 次要（风险、待拍板 Q 列表，先拍影响最大的）。

> **为什么强调 MECE**：评审最常见的两类硬伤——「漏了一种情况」（不穷尽，异常/回滚/兼容没覆盖）和「同一件事说三遍」（不独立，显得没想清楚）。MECE 是一次同时堵住这两个口子的分类纪律。

## 二、SCQA 开场：背景与目标这样写

「序言四要素」，专治「上来就讲方案、评委不知道你要解决啥」。背景与目标一节按 **S→C→Q→A** 四步走，每步一两句，不超过一屏：

| 步 | 名称 | 写什么 | 示例 |
|---|---|---|---|
| **S** | 情景 Situation | 大家都认同的现状事实（带数字） | 「客户端目前直连服务端 WS，3 个消费方各自硬编码 runtime 分支」 |
| **C** | 冲突 Complication | 打破现状的问题 / 变化 / 痛点 | 「新增一种 runtime 时，3 处分支都要改，上周因漏改一处线上请求卡死 2h」 |
| **Q** | 疑问 Question | 由冲突自然引出的那个待解问题 | 「如何让新增 runtime 不再散弹式改动多个消费方？」 |
| **A** | 回答 Answer | 你的方案一句话（就是全文塔尖） | 「引入 runtime provider 抽象层，把分支收敛到单一注册点，新增 runtime 只改 1 个文件」 |

> **为什么用 SCQA**：它保证「问题」和「方案」严丝合缝对齐——A 必须正好回答 Q，Q 必须正好来自 C。评审时评委顺着 S→C→Q 走一遍，会自然认同你的 A，而不是质疑「你为什么要做这个」。A 这句话之后应当能直接接「执行摘要」。

## 三、突出重点：三层强调机制（缺一层重点就沉底）

评委是「扫读」不是「精读」的。重点必须靠**版式**跳出来，不能指望评委读到第三段自己悟。三层，从粗到细：

### 文档级 —— 执行摘要（电梯陈述）

头部信息表**之后、正文之前**，用一个独立块给全文塔尖，**3–5 行**读完就知道「做什么 / 为什么 / 影响面 / 要拍什么」：

```
> **执行摘要**
> - **做什么**：<一句话方案，就是 SCQA 的 A>
> - **为什么**：<一句话动机，就是 SCQA 的 C→Q>
> - **影响面**：<触及的包 / 是否动契约·DB·钱 / 灰度与回滚一句话>
> - **要你拍**：<本次评审真正要决策的 1–3 件事，指向 §待团队拍板>
```

**为什么值得单列**：评审群里一半人只会看这 5 行决定要不要认真读、要不要来评审。它也是你现场开场的逐字稿。写不出这 5 行 = 自己还没想清楚。

### 章节级 —— 每节一句话 TL;DR

每节标题下第一行用 `> 一句话：…` 收束本节结论（全文统一）。评委只读所有节的「一句话」就能拼出全局。

### 句子级 —— 让关键信息物理跳出

- **加粗结论 + 每条 bullet 首词加粗**：判断、取舍结论、约束数字加粗；长 bullet 列表让每条**首词/首短语加粗**当「主题词」，评委扫首词就能跳读。全加粗＝没重点。
- **变更点标注**：迭代已有系统时，新增/改动处用 **加粗 + `⬅ 新增`/`⬅ 改动`**，让评委一眼看到 diff。
- **`> ❗ 最关键的判断：…` 聚光灯**：当某一句话会**推翻先前设计或决定成败**时，单独用 `> ❗ **最关键的判断：**…` 拎出来，别让它淹在正文里。全文这种聚光灯不超过 2–3 处，多了就不聚光了。
- **代码/DDL 块后补一句 recap**：贴完 SQL/TS/DDL/图，紧跟一行 `> …` 把「这块要读者记住的那一点」直接说出来，别让评委自己从代码里推。
- **用表/图/代码块承载结构**：概念用表、流程用图、DDL/接口用代码块——版式本身就是重点分级，纯文字段落是重点的坟墓。
- **零客套**：删掉「综上所述」「众所周知」「随着业务发展」这类填充词，它们稀释重点。

### 收尾 —— 首尾呼应（bookend）

长文档在**结尾再用一句 `> 一句话收束：…` 复述塔尖**，和开头的执行摘要/`> 一句话：` 首尾夹住全文。评委读完最后一句，脑子里留下的正好是你要他记住的那句。

> **长文档额外要求（>400 行 / >8 节）**：每 3–4 节给一个**中场小结**（一句 `> 小结：到这里我们已确定 X、Y，接下来解决 Z`）。大文档的通病就是「早早给了推荐方案，然后 1000+ 行类型定义没有任何中途小结」——评委翻到中间就迷路了。中场小结是长文档的路标。

## 四、「读标题即读全文」自检（金字塔立没立住，这一测就知道）

写完后做这个 60 秒测试——它同时验证「结论先行 + 以上统下 + 突出重点」三件事：

> **只读**「执行摘要 + 每个章节标题 + 每节的 `> 一句话`」，从上到下一遍。
> **通过条件**：这条「骨架路径」本身就讲完了一个完整、自洽的故事；且每个结论下面都有论据/图/数据支撑（没有悬空的断言）。

**关键推论：标题要扛信息，不能是哑名词。** 标题是塔身的分论点，本身要携带结论：

| ❌ 哑标题（评委得读完才知道讲了啥） | ✅ 带结论标题（扫标题就懂） |
|---|---|
| 3.2 方案设计 | 3.2 方案设计：用 provider 抽象替换 3 处硬编码分支，改动收敛到 1 个注册点 |
| 5. 存储设计 | 5. 存储设计：复用现有表加 1 列，不新增表、不迁移历史数据 |
| 7. 上线与回滚 | 7. 上线与回滚：一键开关全收敛，灰度 1%→100%，回滚不留脏数据 |

> 现场评审时，你的翻页节奏就是这条骨架路径。骨架顺了，讲解自然顺；骨架跳跃，讲到哪评委问到哪。

## 五、逐节「必须先行的那句结论」速查

每节开头那句 TL;DR 不是随便写，它有固定的落点。起草时对着填：

| 节 | 第一句必须给出的结论 |
|---|---|
| 1 背景与目标 | 用 SCQA 的 A：一句话方案 + 预期收益数字 |
| 3.2 方案设计 | 选了哪个方案、一句话为什么是它（不是罗列备选） |
| 4 接口/协议 | 新增/改动几个接口、是否破坏兼容 |
| 5 存储 | 加表还是改表、是否需要数据迁移 |
| 7 上线回滚 | 有没有一键开关、灰度节奏、回滚是否留脏数据 |
| 8 WBS | 总人力 xPD、关键路径在哪 |
| 10 风险 | 最高的那条风险是什么、兜底是什么 |
| 11 待拍板 | 本次评审要拍的 N 个决策一句话各是什么 |

## 六、金字塔 · 突出重点自检（并入第 3 步 lint 门禁）

草稿完成后逐条打勾，命中即修：

- [ ] **有执行摘要**，且 3–5 行读完知道 做什么/为什么/影响面/要拍什么。
- [ ] **每节第一句是结论**，不是背景铺垫、不是备选罗列。
- [ ] **每个章节标题携带结论**（能通过「读标题即读全文」测试）。
- [ ] **背景与目标走 SCQA**，A 严丝合缝回答 Q。
- [ ] **同层分组 MECE**：非目标 ✅/⏭️/❌、风险按维度、异常链路无遗漏、各组不重叠。
- [ ] **组内单一逻辑顺序**（时间/结构/程度/演绎，不混用）。
- [ ] **重点靠版式跳出**：结论加粗、变更点 ⬅ 标注、结构进表/图/代码块。
- [ ] **零客套**：无「综上所述/众所周知/随着…发展」填充词。
